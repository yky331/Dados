Armazenagem de dados e sua cronologia

O que é um dado, como ele é guardado e como chegamos aos bancos de dados atuais.

O que é um dado?

Para o computador, um dado é o registro de um fato qualquer, guardado em representação binária: apenas zeros e uns.

Mas como a letra “A” vira zeros e uns? Cada caractere recebe um código binário numa tabela de caracteres. A tabela original, da qual as outras derivam, é a tabela ASCII (American Standard for Coded Information Interchange). Segundo o material, cada caractere ocupa 8 bits, o que dá 2⁸ = 256 combinações diferentes.

Pense assim: são 8 lâmpadas em fila. Lâmpada acesa = 1, apagada = 0. Cada combinação de lâmpadas representa um caractere diferente. Foi isso que você fez no topo da página.

Repare que “a” e “A” têm códigos diferentes. O 0 vale 30 em hexadecimal e o A vale 41, como na tabela do material.
Nota: o ASCII original usa 7 bits (128 símbolos); as versões de 8 bits (256) o ampliam. Para a prova, siga o material: 8 bits.

Do caractere ao banco de dados

Caracteres juntos formam palavras e números. Quando um conjunto de caracteres tem significado (um nome, uma idade, um salário), ele é um campo. Vários campos sobre a mesma pessoa ou coisa formam um registro. Vários registros do mesmo assunto formam um arquivo (que no banco de dados chamaremos de entidade ou tabela). E o conjunto organizado de tudo isso é o banco de dados.

O SGBD: o “gerente” do banco de dados

Com o modelo relacional, surgiu um conjunto de softwares para cuidar de toda a informação guardada e controlar quem pode acessá-la: o Sistema de Gerenciamento de Banco de Dados (SGBD). Ele guarda não só os dados, mas também a descrição de como eles estão guardados (estrutura, tipos e restrições), em uma área chamada catálogo.

É o primeiro modelo. Os dados ficam em registros ligados por uma relação pai-filho, formando uma árvore. O primeiro registro é a raiz. Um pai pode ter vários filhos ou nenhum, e para chegar a um filho é preciso passar pela raiz.

Parecido com o hierárquico, mas sem hierarquia rígida: um registro pode se ligar a vários outros (formato de grafo), e é possível chegar direto a qualquer registro, sem passar pela raiz.

Usa a teoria da orientação a objetos (a mesma das linguagens de programação, como Java). Cada registro lembra uma classe: guarda dados e também comportamentos.

É o modelo da maioria dos SGBDs atuais e o foco deste curso. Os dados ficam em tabelas (relações): cada coluna é um campo e cada linha é um registro. As tabelas se ligam por campos em comum, o que evita repetir informação.

O resultado de uma consulta também é um conjunto de linhas, como uma “tabela virtual” que só existe enquanto a consulta está ativa.

Diagrama de entidade e relacionamento

Como desenhar o banco de dados antes de construí-lo.

O que é o DER?

Todo banco de dados nasce de um projeto: quais tabelas existirão e como elas se relacionam. Para planejar isso usamos o Modelo de Entidade e Relacionamento (MER), criado por Peter Chen em 1976. Sua representação gráfica é o DER (diagrama de entidade e relacionamento). É uma modelagem conceitual.

Analogia: o DER é a planta da casa. Você desenha e conversa com o cliente antes de comprar tijolo.

Uma frase simples ajuda a entender: “Cliente compra Produto”. “Cliente” e “Produto” são entidades; “compra” é o relacionamento.

Para praticar, o material usa o BR Modelo Web (app.brmodeloweb.com), onde você cria os diagramas e gera o modelo lógico automaticamente.

Entidade

É a representação abstrata de um objeto do mundo real: cliente, funcionário, agência, produto, venda. No desenho, vira um retângulo com o nome. Mais tarde, cada entidade vira uma tabela, e cada linha dessa tabela é uma instância (um cliente específico, por exemplo).

Atributos e seus tipos

Atributos são os valores que descrevem a entidade. Na entidade Cliente: nome, endereço, CPF, telefone. Eles aparecem como círculos. Existem quatro tipos. Clique em um tipo para destacá-lo no desenho:

O atributo determinante (chave) identifica cada registro de forma única. No exemplo, o ID_Cliente. Ele tem três características:

• não pode ser alterado; • deve existir em toda entidade; • pode ser formado por mais de um atributo.

Por que não usar só o nome? Porque podem existir dois clientes chamados “Kayky Dorta”.

Especialização e generalização

Algumas entidades têm “subtipos”. Uma conta corrente pode ser de pessoa física ou pessoa jurídica. Dizemos que pessoa física e jurídica são especializações, e que conta corrente é a generalização delas.

Para classificar, responda duas perguntas. Use os botões e veja exemplos reais de cada caso:

1) Toda ocorrência precisa ser de alguma especialização?

2) Pode ser de mais de uma ao mesmo tempo?

Resumo para decorar: Total = ninguém fica de fora. Parcial = pode haver “outros”. Disjuntiva = é uma ou outra. Compartilhada = pode ser várias ao mesmo tempo.

Relacionamentos e cardinalidade

Um relacionamento é a associação entre entidades. Ele tem uma cardinalidade, escrita como (x, y): x é o mínimo e y é o máximo. Lê-se: “uma instância de A se relaciona com, no mínimo x e no máximo y, instâncias de B”. (Mínimo 0 significa que o relacionamento é opcional.)

Modelagem de banco de dados

O caminho do pedido do cliente até as tabelas.

O que é modelar?

Modelagem é um processo de abstração: definir quais são as entidades, quais atributos as descrevem, quais relacionamentos existem e de que tipo. Quanto melhor o modelo, mais eficiente o banco será para representar os dados reais da empresa.

As 3 fases da modelagem

A modelagem passa por três fases. A quarta, o modelo físico, vem na próxima unidade. Clique em cada fase:

Exemplo completo: clientes, produtos e vendas

Vamos seguir um único problema pelas três fases, como no material. Escolha a etapa:

Este é o texto que sai da conversa com o cliente. Ligue os destaques para achar o que importa:

Uma empresa possui um cadastro de clientes, identificado por um número, com nome, CPF, endereço e telefone. Da mesma forma, existe um cadastro de produtos, identificado por um número, com descrição e valor.

A um cliente é possível vender um ou mais produtos. Na venda, registra-se a data, qual é o cliente e quais produtos ele compra, com a quantidade de cada um, para calcular o valor total.

Uma venda é feita a apenas um cliente, mas o mesmo produto pode ser vendido a vários clientes em vendas diferentes.

Agora o texto vira desenho. Não há tecnologia definida ainda: é fácil de mostrar ao cliente.

Como ler: um cliente faz várias vendas (1 para N); cada venda é de um só cliente. Venda e Produto são muitos para muitos, então o relacionamento vira uma entidade associativa (“Item da venda”), que guarda a quantidade de cada produto na venda.

Com a tecnologia definida, o diagrama vira tabelas. Cada entidade virou uma tabela; atributos-chave viraram PK (Primary Key, chave primária); e para ligar tabelas surgiram campos FK (Foreign Key, chave estrangeira). Aqui também se definem os tipos de dados (veremos nas próximas unidades).

Mini-projeto: biblioteca

Uma biblioteca cadastra leitores (matrícula, nome, e-mail) e livros (código, título, autor). Um leitor pode pegar vários livros emprestados ao longo do tempo, e um mesmo livro pode ser emprestado a vários leitores em momentos diferentes. Em cada empréstimo, registram-se a data de retirada e a data de devolução.
